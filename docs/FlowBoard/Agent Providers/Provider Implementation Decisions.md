# Provider Implementation Decisions

The calls made while building the [[Claude Code Adapter]] and the [[OpenCode Adapter]] on 2026-10-18, and the review findings left for later. Both providers were built on branch `feature/agent-providers`, merged into `dev` on 2026-10-19, and live under `code/flowboard/packages/adapters/src/agent/`. Each was built from a plan (`docs/superpowers/plans/2026-10-18-agent-providers-claude-code.md` and `…-opencode.md`) and checked by an independent whole-branch review; the review's critical and important findings were fixed test-first before this note was written.

Port-level decisions (new `RunSpec` fields, the `usage` event, `pid` as a promise, and so on) are recorded against their questions in [[Agent Providers Open Questions]]. This note covers the rest.

> [!check] Changed 2026-10-22
> C11 was revised, and C13 to C18 and O17 to O19 were added, on 2026-10-22. They are Claude's decisions, taken while fixing a docs-and-code audit; Alex has not reviewed them. The guard rows (C11, C13, C14, C18) cover shared code in `core/src/guard.ts`, used by both providers. The same day, C5, C6, C12, O8 and three deferred issues were corrected to match the code. A deferred issue found that day, letter case in `denyPaths`, was fixed the same day and is now part of C14.

## Claude Code provider

### Decisions

| # | Decision | Why | Cost if wrong |
|---|---|---|---|
| C1 | Built on the existing branch `feature/agent-providers`, not the plan's `feature/agent-providers-claude` | The owner asked for it | A branch rename |
| C2 | Kept the PRD's CLI flag tables in [[Claude Code Adapter]] and added a *Built on the Agent SDK* section that supersedes them | The notes are source-cited; the tables record what the PRD says | One table to delete |
| C3 | The live guard test asserts the hook's own message (*"Write outside the worktree"*), not just any failed tool call | A test that passes on its first run must prove the hook, not a coincidence | None |
| C4 | `stop()` after the result no longer relabels a finished run as stopped; graded important, not minor | A graceful shutdown would mark completed steps cancelled and re-run them | None |
| C5 | Shell writes outside the worktree (redirects, `cp`, `tee`) are not blocked by the guard; only a recursive `rm` is checked against the write roots (C11) | The guard reads only the command's text; the sandbox tier (designed, not built) is meant to be the floor | On the host tier, a run can write anywhere the owner can |
| C6 | Only `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` are stripped from the run's env; `ANTHROPIC_BASE_URL` and `CLAUDE_CODE_USE_BEDROCK` / `VERTEX` pass through | The sandbox tier (designed, not built) will need `ANTHROPIC_BASE_URL` for its egress proxy | A worker env with those set silently reroutes runs |
| C7 | The adapter does not check which provider a `CapabilityPack` was made for | Capability negotiation and pack validation belong to the runner ([[Capability Negotiation]]) | A pack made for another provider gets mounted on Claude |
| C8 | `ReplayProvider.result` still settles only while its `events` are read | It is a test double; the limit is marked in the code | A runner test that never reads events hangs |
| C9 | Resume was not checked for replayed history | Verifying it needs a paid run, and the plan does not exercise resume | A resumed run's viewer may show earlier messages again |
| C10 | No schema version `v` on `NormalizedEvent`, no CLI/SDK version check, `dontAsk` as the default permission mode | Listed as skipped or by design in the plan | Small follow-ups |
| C11 | (Revised 2026-10-22) A recursive `rm` must stay inside the write roots: the PRD's *"rm -rf outside the worktree"*. The rule is built into `checkToolCall` and derived from `writeRoots`, so it applies whenever `guards` is set, even with no `denyCommands`; it left `DEFAULT_DENY_COMMANDS`. A recursive `rm` (`-r`, `-R`, any short-flag group holding `r` or `R`, `--recursive`; options before or after the operands, `--` ends them) is refused when an operand lands outside every root or is a root itself (*Recursive rm outside the worktree*). Operands resolve where the shell runs: Claude's hook passes the shell's current folder (a `cd` persists between Bash calls), OpenCode's plugin passes bash's `workdir`, and a literal `cd` or `pushd` earlier in the command is followed, also after a shell keyword (`if cd /tmp; then rm -rf foo; fi` is refused). A link operand is the link itself, or its target when written with a trailing slash. `.` passes, since `rm` refuses it. Also refused: an operand the shell expands (`$`, a backtick, `\`, a leading `~`, a dot-segment holding `*`, `?` or `[`, or a brace other than a simple list such as `{dist,build}`, which is expanded and each part checked), a relative operand after a `cd` the guard cannot follow (`cd "$X"`, `cd ~`, a `cd` with an option such as `cd -` or `cd -P x`, a bare `cd`), and `rm` fed by `xargs`. `find … -exec rm -rf {} +` (or `{} \;`) is checked against find's starting points. Redirections are not operands. The command is split on `;`, `&`, pipes, parentheses and newlines, backtick substitutions and line continuations included, with quotes stripped, so `bash -c "rm -rf /"`, `sudo rm`, `/bin/rm` and `\rm` are caught. A plain `rm` and `git rm` are not checked | The 2026-10-18 rule was a regex on the first operand. It refused an absolute path inside the folder, and let `rm -rf $HOME`, `rm -rf ./x ~`, `rm -r -f ./x /` and `rm -rf "/"` through. It sat in a list only `run-agent` passed, so a caller passing `{ writeRoots }` alone got no `rm` check. A review of the first rewrite found that OpenCode's `workdir`, a `cd`, `xargs` and backticks still got past it | Still reads text: a script, `eval`, `find -delete`, or another command that deletes (`git clean`, `mv`, `truncate`) gets around it. The sandbox tier (designed, not built) is meant to be the floor |
| C12 | Both providers send `SIGKILL` when a child ignores `SIGTERM` for 5 s (`killGraceMs` option; shared helper `adapters/src/exec/terminate.ts`) | A stuck CLI or server kept `result` pending forever. That holds for OpenCode, and for Claude only with a fake `query()` in tests: on abort, Agent SDK 0.3.302 already closes stdin, sends `SIGTERM` 2 s later and `SIGKILL` 5 s after that, and only then forwards the abort to the provider | A child that needs more than 5 s to shut down cleanly is cut off. On Claude the provider's `terminate()` runs about 2 s after `stop()`, its default 5 s grace races the SDK's own, and a `killGraceMs` above 5000 cannot lengthen the grace |
| C13 | (2026-10-22) A file-edit write is checked where it lands: links are followed, a dangling one too, and a missing tail is kept as written. A leading `~/` is the home folder. The write roots are resolved the same way. A write through a link inside a root to outside it is refused with *Write through a link to outside the worktree: \<path\> -> \<where it lands\>* | The guard compared path text, so a `Write` or `Edit` through a link inside the folder landed outside it unchecked, and `~/.bashrc` was checked as `<folder>/~/.bashrc` and passed. A side effect: on macOS a write to `/tmp/x/a.md` with the folder `/private/tmp/x` is now allowed | The check runs before the tool does, so a link made between the two is not seen |
| C14 | (2026-10-22) `denyPaths` keeps Node's `path.matchesGlob`, on the path relative to the run's folder (resolved), with dot names matched: `*` and `**` match names that start with a dot (`secret/**` covers `secret/.env`, `*.lock` covers `.x.lock`), and a glob that names a dot-file or dot-folder matches it beside other dot names (`**/.env` covers `.config/.env`, `.github/**` covers `.github/.hidden`). `*` does not cross `/`; `**` does. On macOS and Windows the path and the glob are lower-cased before matching (`fold`), so letter case is ignored, as the disk ignores it; on Linux it counts (resolved 2026-10-22) | Node's matcher has no `dot` option and skipped dot-files, so `secret/**` let the agent write `secret/.env`; the first fix still missed globs that name a dot name. Node ignores case on macOS and Windows only in a glob's wildcard parts, so `docs/**` did not refuse `DOCS/a.md`, which a case-insensitive disk writes into `docs/`. Keeping Node's matcher needs no new dependency | `*.lock` still covers only the lock files at the top of the folder; a YAML must say `**/*.lock`. Case follows the platform, not the disk: a case-sensitive volume on macOS still has case ignored, and a case-insensitive one on Linux does not |
| C15 | (2026-10-22) Both providers: `Usage.numTurns` is the main agent's turns (model calls); subagents' tokens and cost count, their turns do not. Claude's live `usage` events count the main agent's finished messages (`message_stop` with no `parent_tool_use_id`), and its result uses the CLI's `num_turns`. OpenCode counts the root session's `step-finish` parts only | Claude's live events always said 0, and OpenCode counted subagent steps too, so the field meant different things mid-run | A run that works mostly through subagents shows few turns, though their tokens and cost still count |
| C16 | (2026-10-22) Both providers: a run stopped, or failed, before its result reports the last running totals from its `usage` events as `RunResult.usage`, not zero. On Claude those carry tokens and turns but no `costUsd` (Claude prices a run only in its result), so a stopped Claude run needs pricing from tokens; on OpenCode they carry cost | A stopped or crashed run reported zero usage even after costed events, so a cost ledger reading `RunResult` would record $0 for a run that spent money | Tokens spent after the last `usage` event are not counted |
| C17 | (2026-10-22) `ReplayProvider` fails the run on a scripted `error` event (`exitCode: 1`; `error` is the first error's message). `sessionId` rejects with *run ended without a session id* when neither `script.sessionId` nor a `system` event gives one; the `'replay-session'` default is gone. Scripted `usage` events are tracked, so a stop keeps the totals. Replay still passes `outcome` through from a scripted `result`, and is the only provider that sets it | A runner tested on Replay never saw a failed run or a missing session, which the real providers produce | A script that relied on the default session id, or on an error event passing, now fails |
| C18 | (2026-10-22) The `git push` and `git reset --hard` rules in `DEFAULT_DENY_COMMANDS` allow git's global options before the subcommand: `git -C . push`, `git -c k=v push`, `git --no-pager push` and `git reset -q --hard` are refused; `git reset --soft` and `git log` pass. The list still has three entries; the refusal message shows the longer regex | The old rules needed the subcommand straight after `git`, so `git -C . push` got through | Still a regex on the text: a script, a git alias or `eval` gets around it |

### Deferred issues

| Issue | Effect | Where |
|---|---|---|
| A file inside the worktree whose name starts with `..` (e.g. `..foo`) is denied | The agent cannot write such a file, or remove it with a recursive `rm` | `core/src/guard.ts` |
| A child killed by a signal reports exit code 1 | The runner cannot tell an out-of-memory kill (transient, worth retrying) from a plain failure | `claude/provider.ts` |
| The plugin-loaded check resolves relative paths against the worker's cwd and ignores symlinks | A relative or symlinked plugin dir fails the run although it loaded (fails safe) | `claude/provider.ts` |
| The provider's abort listener duplicates the SDK's own kill, and misses a signal that was already aborted | Not dead code: the SDK forwards the abort about 2 s after `stop()`, right after its own `SIGTERM`, and the listener's `terminate()` then sends a second `SIGTERM` and arms a second `SIGKILL` that races the SDK's. Every Claude stop waits those 2 s, and `killGraceMs` can only shorten the grace (C12) | `claude/provider.ts` |
| Importing `@flowboard/adapters` loads the Claude SDK even for replay-only use | Slower imports in runner tests | `adapters/src/index.ts` |

## OpenCode provider

### Decisions

| # | Decision | Why | Cost if wrong |
|---|---|---|---|
| O1 | The capture test reads the root session id from the final `session.idle` | The capture subscribed after creating the session, so it has no `session.created` | None |
| O2 | MCP config entries leave out `environment` when a tool server has none | The plan's expected value contradicted its own JSON round-trip test | None |
| O3 | The provider answers every `permission.asked`, not only those of the run's sessions | One server per run means every request is the run's | If servers are ever pooled, filtering by session must come back |
| O4 | The event stream is subscribed with `{ signal, sseMaxRetryAttempts: 1 }`; the provider waits for `server.connected` before prompting, and a dead server aborts the stream | The SDK's stream connects lazily and retries forever | None |
| O5 | `stop()` after the result does nothing; a stop before it reports `stopped` even though the abort makes OpenCode report the session idle | Matches the Claude provider | None |
| O6 | Server start failures are read on `close`, not `exit` | So the server's full error output is in the message | None |
| O7 | Changed *"the only real one"* to *"the first real one"* in [[Claude Code Adapter]] | No longer true | One sentence |
| O8 | Inherited `OPENCODE_CONFIG` / `OPENCODE_CONFIG_DIR` stripping graded important, not minor, and fixed; O17 widened it to every `OPENCODE_*` setting | The plan's isolation rule covers them | None |
| O9 | `~/.opencode` and OpenCode's remote well-known config still load | Accepted by the plan; `~/.opencode` does not exist on this machine | Extra config on another machine |
| O10 | The guard plugin and `@flowboard/core` load from host paths | Same limit as Claude `plugin_dir` mounts | A container `ExecHost` cannot use them; a guarded run there fails loudly instead of running unguarded |
| O11 | Tool-policy patterns pass through as written (`Bash(pnpm *)` here, `Bash(pnpm:*)` in Claude Code) | [[Run Spec]] defines no glob syntax | A pattern may match on one provider and not the other |
| O12 | A model with no listed price reports cost 0, so `maxBudgetUsd` never trips for it | Mirrors Claude | An unpriced model runs with no budget cap |
| O13 | No server pooling, no re-attach after a worker restart | Listed as skipped in the plan | About a second of startup per run |
| O14 | Reading `*.env` and `*.env.*` asks (refused in a headless run unless the mode answers everything); `*.env.example` stays allowed. The rules sit after the plain allows, so allowing `Read` does not re-open them, and before specific ones, so an explicit `Read(.env)` still does | OpenCode's own default; secrets in the project would otherwise go to the model provider. The final review found an explicit `Read(.env)` was silently overridden at first | None |
| O15 | `maxTurns` sets `steps` on `build`, `plan`, `general` and `explore` | Subagents had no step limit, and on an unpriced model the budget cap does not work either | None |
| O16 | `startServer` keeps an `error` listener for the server's whole life, adding the message to the stderr tail | A late child error (e.g. a failed kill) was an uncaught exception | None |
| O17 | (2026-10-22) The server inherits the owner's environment minus every `OPENCODE_*` variable except the credentials `OPENCODE_API_KEY` and `OPENCODE_AUTH_CONTENT`, and minus `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN`, as on Claude (C6). Then the adapter sets its own: `XDG_CONFIG_HOME` (a fresh temp folder), `OPENCODE_DISABLE_PROJECT_CONFIG`, `OPENCODE_DISABLE_CLAUDE_CODE`, `OPENCODE_DISABLE_AUTOUPDATE`, `OPENCODE_SERVER_PASSWORD`, `OPENCODE_CONFIG_CONTENT`, and `FLOWBOARD_GUARDS` when guards are set | The OpenCode 1.19.3 binary knows about 80 `OPENCODE_*` names. An inherited `OPENCODE_PERMISSION` was merged into the rules subagents run under, and an exported Anthropic key let an `anthropic/...` model bill the API directly | An `OPENCODE_*` setting the owner relies on no longer reaches runs. Still not isolated: admin-managed config (a system config folder, macOS managed preferences, an org config) and `auth.json`, so an `anthropic/...` model runs only if `auth.json` (or `OPENCODE_AUTH_CONTENT`) holds an Anthropic credential |
| O18 | (2026-10-22) Each injected tool server's allow (`<server>_*`) sits after the allow list and before the deny list, so an explicit deny of the ask tool (`mcp__flowboard__ask_user`, `mcp__flowboard__*`, `*`) wins, as it already did on Claude through `disallowedTools`. No allow list, nor a missing one, can lock out asking | The two adapters disagreed: OpenCode put the pre-approval last, so a deny could not take asking away there. The port's promise now covers allow lists only | A broad deny such as `*` takes asking away too |
| O19 | (2026-10-22) A `native` CapabilityPack's config is applied first; the adapter's own keys (`permission`, `experimental`, and when set `mcp`, `skills`, `agent`, `plugin`) then replace the pack's same top-level keys. Keys the adapter does not set, such as `instructions`, are kept | Applied last with `Object.assign`, a pack could drop the permission rules, the step limits, the MCP no-timeout, the ask_user server or the guard plugin | The replace is shallow: a pack's own `mcp` servers or `plugin` entries are lost when the run sets those keys. `run-agent` never builds native packs, and the Claude adapter ignores them |

### Deferred issues

| Issue | Effect | Where |
|---|---|---|
| The server password, `OPENCODE_CONFIG_CONTENT` and `FLOWBOARD_GUARDS` are visible to the agent's shell commands and local MCP servers | A run could reach its own server and loosen its own permission rules, or run commands through the server's `POST /session/{id}/shell` and `POST /pty`, which skip the guard plugin and the permission ask. The guard plugin checks only the agent's own tool calls. In practice an agent needs shell access already to read its env. Documented in [[OpenCode Adapter]] | `opencode/options.ts` |
| `--port 0` on the real server tries 4096 first; the fake server picks a random port | The concurrency test does not exercise real port contention | `test/fixtures/fake-opencode.mjs` |
| The MCP permission key does not apply OpenCode's name sanitizing | A tool server name containing `.` or `:` will not match its allow rule | `opencode/permissions.ts` |
| `partial_stream` is advertised, but live text deltas are dropped | Only per-step usage arrives mid-run | `opencode/normalize.ts`, `opencode/provider.ts` |
| A text part cut off by an abort before it ends is dropped | The partial text never reaches the viewer | `opencode/normalize.ts` |
