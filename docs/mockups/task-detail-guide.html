Three alphabets

The screen uses three sets of marks, and they mean different things. The spine is about steps, the story icons are about runs, and the verdict badges are about work items. Don't read one as the other.

The four tabs

Same task, four questions. Number keys 1–4 switch between them.

Everything is a real file. Each step declares what it produces, and FlowBoard files the output into the task's own copy of the repo, committed on its own branch. That is why Files is a list of paths rather than a database view — and it's what makes the next section possible at all.

Plan vs built — the four verdicts

The plan is a real file with numbered items and acceptance criteria. The build's output is a real patch. So the two can be lined up mechanically: each item gets a verdict based on what is actually in the working tree, not on what the agent said it did in its summary.

What a deviation looks like

Item 2 asked for family-wide revocation. Something was built, a file was changed, and a diff skimmed quickly looks like progress:

@@ src/auth/family.ts + await revoke(token.jti) // TODO: walk the family and revoke siblings — review.md flagged this as a deviation from plan item 2

One token revoked, not the family. The acceptance criterion — "replaying an old token logs the session out everywhere" — is not met, and no test covers it.

Deviated is the verdict to fear, not missed. A missing item is loud: the column is empty and you notice. A deviation is quiet — it has a file, a diff and a green test run behind it. This view exists mostly to make that difference visible in one glance.

Where a task can be, and what moves it

Solid arrows happen on their own. Dashed amber arrows are yours — they are the only places a person moves a task.

Pause, Send to backlog and Cancel are not drawn because they can happen from anywhere. Pausing and sending back to the backlog both keep the workspace; cancelling stops any running agents and tidies up. In every case the workspace survives until you clean it up yourself, and only once the task is finished or cancelled.

Making the call at a gate

The screen is at a review gate with two flags against it. Step through how to read the evidence, then take either decision and see what it costs.

walkthrough auth-refactor, at the review gate

Every control

Stopping never refunds. Cancelling a task, or sending a step back, does not recover what has already been spent — it moves that spend into wasted and stops the future spend. The only free decision on this screen is approving.

The numbers, and what they don't say

Agent time is not wall-clock

This task shows 22m of agent time, but it has been open far longer. The gap is time nobody paid for: 2m 14s while Plan waited on your answer, and the 5m and counting since the review gate opened. A run that asks you a question saves its place and stops billing, so a slow answer costs you calendar time and nothing else.

Kept, wasted, bill

  • Kept — spend on attempts whose output is still in the workspace.
  • Wasted — spend on attempts that were thrown away. Here, $0.48 on a build the sandbox killed for reaching registry.npmjs.org, which wasn't on that step's allowlist.
  • Bill — the two added together. It never goes down. Sending a step back moves money from kept to wasted; it does not reduce what you owe.
