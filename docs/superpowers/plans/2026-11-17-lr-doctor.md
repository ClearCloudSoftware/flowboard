# lr-doctor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `pnpm lr-doctor` reports whether this machine can run the user's Lamproom projects, as a table or as
`--json` that a later UI route returns unchanged.

**Architecture:** A pure **needs** step reads projects, settings and flows from disk and decides what each check is
needed for. A **checks** step runs injectable probes, which wrap the existing functions, in parallel with a timeout,
and builds a `DoctorReport`. A thin **CLI** prints the report as a table or as JSON and sets the exit code. A UI route
would later call `runDoctor()` directly.

**Tech Stack:** Node 24, TypeScript run directly by `node` (type stripping), `node:test` + `node:assert/strict`,
`node:util` `parseArgs`.

**Spec:** `docs/superpowers/specs/2026-11-17-lr-doctor-design.md`. Read it first; this plan argues from it.

**Setup:** The worktree is `.claude/worktrees/lr-doctor`, on branch `feature/lr-doctor`. It has no `node_modules`
yet, so run `pnpm install` in the repo root once before Task 1. Run every command below from the repo root.

## Global Constraints

- Read-only: never install, build, log in, or write a file. The one exception is `refreshOllama`, which writes
  `ollama-models.json`.
- Reuse the existing probes: `dockerNotReady`, `dockerHasGvisor`, `dockerDefaultMemoryMb` (project.ts),
  `harnessStatus` (harnesses.ts), `ghStatus` (github.ts), `refreshOllama` (ollama.ts), `keyView`, `savedKey` and
  `testKey` (openrouter.ts), `slackTokens` and `slackCall` (slack.ts), `boxImage` (isolation.ts), `agentNeeds` and
  `NEEDS` (flow-config.ts), `resolveSettings` (settings.ts), `readAppSettings` and `defaultDataDir`
  (app-settings.ts), `readProjects` (projects.ts). Never write a second copy of any of them.
- Run CLIs with argument lists, never through a shell.
- Never put a secret in the output: a key or token shows as "set", its source, and at most its last 4 characters.
- `schema: 1`. Every check id is always present, in this fixed order:
  `node, pnpm, git, data, docker, docker.image, docker.gvisor, token.claude, claude, opencode, uv, openrouter, ollama, github, slack, opensandbox`
- Exit codes: `0` when `summary.ready`, `1` when any check is `fail`, `2` for a bad argument or a crash.
  Warnings never change the exit code.
- Marks: `✓` ok, `✗` fail, `!` warn, `–` skip. Use colour only when stdout is a TTY and `NO_COLOR` is unset;
  `--json` output never has colour.
- Version floors: node fails below 22.18 and warns below 24. pnpm warns when its major version isn't the
  `packageManager` major (10).
- Default timeout per probe: 30 000 ms.

## Review Focus

1. **A probe that hangs**, such as Docker Desktop stuck starting: the doctor still finishes, and that check is `fail`
   (or `warn` if optional) with "did not answer in 30 s". Covered by Task 2,
   `runDoctor: a hung probe times out, the rest still report`.
2. **A fresh clone** with no data folder, no projects and no flows: no crash, `ready: true`, and Docker shows `warn`
   "needed for new projects". Covered by Task 1, `readSetup: missing data and flows folders are empty, not errors`,
   and Task 2, `runDoctor: fresh machine is ready with warnings`.
3. **A broken flow file** in the flows folder: it is listed in `context.unreadableFlows`, and every other flow still
   counts. Covered by Task 1, `readSetup: a flow that does not load is listed, others still count`.
4. **Secrets leaking** into the table or the JSON: neither contains the key or token text. Covered by Task 3,
   `doctorCli: no secret appears in table or JSON`.
5. **Polluted `--json` stdout** (colour codes, stray lines): stdout is exactly one `JSON.parse`-able document.
   Covered by Task 3, `doctorCli --json: stdout is one JSON document, no ANSI`.

- [ ] **Step 3: Implement `realProbes` and `runDoctor` in `doctor.ts`.** The rules:
  - **Status:**
    - A healthy result is `ok`.
    - A degraded result is `warn`: an old node or pnpm, or Slack with a bot token but no app token.
    - A broken result is `fail` when the need is `'yes'`, and `warn` when it is `'new'` or `'no'`. A `'no'` result
      adds "(optional)" to its detail.
    - `needed` is `need === 'yes'`.
  - **Always probed:** node, pnpm, git, data, docker, claude, opencode, uv, ollama and github. These run whatever the
    need. `docker` runs `version('docker')` first (missing → "install Docker"), then `probes.docker()` (down →
    "Start Docker Desktop").
  - **Skipped when the need is `'no'`:** docker.image, docker.gvisor, token.claude, and opensandbox. Their detail
    reads "not needed: <reason>".
  - **openrouter:** skipped when it isn't needed and no key exists. Otherwise the key comes from
    `env.OPENROUTER_API_KEY ?? savedKey(dataDir)` and goes to the probe. The detail is
    "<env|saved> key …<last4>, $X left", or "no credit limit" when `remainingUsd` is null.
  - **slack:** skipped when there are no tokens ("no tokens saved: escalation goes nowhere").
  - **Depends on Docker:** when docker is down, docker.image and docker.gvisor are skipped with "Docker is not
    running".
  - **token.claude:** ok when `env.CLAUDE_CODE_OAUTH_TOKEN` starts with `sk-ant-oat01-`. When `runner === 'terminal'`,
    the detail gains "; checked in this terminal; the app opened from Finder may not have it".
  - **claude:** ok when installed and `signIn.ok`. **opencode:** ok when installed; `signIn.text` goes in the detail.
  - **data:**
    - `dataDir` exists and `accessSync(W_OK)` passes.
    - `projects.json`, if present, passes `JSON.parse`.
    - A missing folder is `warn`: "no data folder yet; the app makes it on first start".
  - **Fix lines:** use the spec's table text and the probes' own messages.
  - **Timeouts:** every probe goes through
    `within(p, timeoutMs ?? 30_000)`. On a timeout the result is broken, with detail "did not answer in N s".
  - **Order:** run every probe at once with `Promise.all`, then assemble the checks in `CHECK_IDS` order.
    `ms` records how long each probe took.
  - **`realProbes`:**
    - `version` uses async `execFile` with a 10 s timeout. ENOENT sets `missing: true`.
    - The sync existing functions are called as they are, with
      `// ponytail: spawnSync probes block the parallel ones; make them async if the doctor gets slow`.
    - `opensandbox` reaches `http://${env.OPENSANDBOX_DOMAIN ?? '127.0.0.1:8080'}/`, and its images go through
      `image()`.
  - **The rest of the report:** `context` comes from `Setup`, and `summary` counts statuses, with `ready` meaning no
    `fail`. `host` is `{ platform, arch }`.

- [ ] **Step 3: Implement `renderReport`, `doctorCli` and `doctor-main.ts`.**
  - **Header:**
    - Line 1: `Lamproom doctor · <macOS|Linux|Windows> <arch> · data <dataDir relative to cwd>`.
    - Line 2: `Projects: name (Tier), … · new projects: Tier`, or `Projects: none yet · …`.
  - **Groups:** in the order Core, Containers, "Agents on this machine", Models, Connections. A group's needed line,
    right-aligned at column 45, is the `why` of its first needed check.
  - **Check lines:** two-space indent, mark, label padded to 13, then detail. The fix goes on the next line, indented
    under the detail, with `→ `. Labels are the spec sample's.
  - **Summary:** `Ready.`, `Ready: N warning(s).`, or `Not ready: N problem(s) stop(s) runs, M warning(s).`
  - **Colours:** green ✓, red ✗, yellow !, dim –. Colour is on when `io.tty && !io.env.NO_COLOR` and the flag isn't
    `--json`.
  - **`doctorCli`:**
    - Arguments go through `parseArgs({ args, options: { json: { type: 'boolean' } }, strict: true })`. A parse error
      prints `usage: lr-doctor [--json]` to err and returns 2.
    - Otherwise run `runDoctor({ runner: 'terminal', env: io.env, ...opts })`.
    - Print `JSON.stringify(report, null, 2)` with `--json`, else the table.
    - Return `ready ? 0 : 1`. A thrown error prints its message to err and returns 2.
  - **`doctor-main.ts`:**
    `process.exitCode = await doctorCli(process.argv.slice(2), { out: (s) => process.stdout.write(s + '\n'), err: (s) => process.stderr.write(s + '\n'), tty: !!process.stdout.isTTY, env: process.env });`
